# 製品仕様書: Explain & Chat for Web Pages

## 1. プロダクト概要

- **プロダクト名（仮称）**: Browser AI Companion（browser-ai-extension）
- **一文での説明**: 任意の Web ページの本文や選択テキストを Side Panel から英語で解説させ、ページ内容を文脈とした AI チャットも行える Chrome 拡張機能（MV3）。
- **ターゲットユーザー**:
  - 英語学習中で、日本語サイト・英語サイトを問わず英文での要約・解説を読みたいユーザー
  - 技術記事やニュース記事を読む際に、AI に質問しながら理解を深めたいユーザー
- **解決する課題**:
  - 任意のページについて、コピペや別タブを開かずに英語の解説を即時に得られないこと
  - ページ内容を踏まえた AI 質問応答を、ページ遷移を阻害せずに行えないこと
- **参考実装との差分（youtube-ai-extension との違い）**:
  - 対象ページが YouTube 動画ページ限定 → **任意の Web ページ全体（`<all_urls>` 想定）**
  - 入力ソースが字幕/動画メタデータ → **ページ DOM の本文抽出 + ユーザー選択テキスト**
  - **対象外（明示）**: Anki 連携、視聴/閲覧履歴トラッキング、クイズ生成、復習スケジューリング

## 2. 機能一覧

### F-001: API キー設定
- **概要**: 設定画面で Anthropic API キーを入力・保存し、拡張機能から Claude API を呼び出せるようにする。
- **ユーザーストーリー**: ユーザーとして、初回利用時に自分の Anthropic API キーを安全に登録し、以降の機能で利用させたい。
- **受け入れ条件**:
  - 設定画面に API キー入力欄（type=password 相当のマスク表示）と保存ボタンがある
  - 保存後にキーが `chrome.storage.local` に保存され、`chrome.storage.sync` には保存されない
  - 保存済みキーは UI 上では伏字（例: `sk-ant-****`）で表示される
  - キー未設定時に Explain / Chat を実行すると、設定画面への誘導メッセージが表示される
- **優先度**: Must

### F-002: モデル選択
- **概要**: Claude のモデルを設定画面で選択でき、Explain と Chat の両方に適用される。
- **ユーザーストーリー**: ユーザーとして、用途やコストに応じて利用するモデルを選びたい。
- **受け入れ条件**:
  - 設定画面に複数モデル（最低 2 種類）から選択できるドロップダウンがある
  - 選択値が `chrome.storage.local` に保存され、再起動後も保持される
  - 未選択時は既定モデルが使用される
- **優先度**: Must

### F-003: ページ本文の DOM 抽出
- **概要**: アクティブタブの DOM から本文相当のテキストを抽出する。`<script>` `<style>` `<noscript>` などは除外する。
- **ユーザーストーリー**: ユーザーとして、ナビゲーションや広告ノイズを除いたページの本文だけを AI に渡したい。
- **受け入れ条件**:
  - `<script>` `<style>` `<noscript>` の内容が抽出結果に含まれない
  - 抽出結果が空文字でないこと（本文を持つ通常ページの場合）
  - 抽出は 2 秒以内に完了する（一般的な記事ページで）
  - 抽出文字数の上限が定義され、上限超過時は切り詰める（切り詰めをユーザーが認識できる表示がある）
- **優先度**: Must

### F-004: 選択テキストの取得
- **概要**: ユーザーがページ上で選択したテキストを Explain / Chat の入力に利用できる。
- **ユーザーストーリー**: ユーザーとして、ページの一部分だけを AI に解説させたい。
- **受け入れ条件**:
  - Side Panel 上に「ページ全体」「選択範囲のみ」を切り替える UI がある
  - 選択範囲が空の状態で「選択範囲のみ」を実行すると、その旨のエラーメッセージが表示される
  - 選択テキストが取得できる場合、抽出結果の先頭は選択テキストと一致する
- **優先度**: Must

### F-005: Explain（英語解説）
- **概要**: ページ本文または選択テキストを Claude API に送り、英語で解説した結果を Side Panel に表示する。
- **ユーザーストーリー**: ユーザーとして、ページ内容を英語でわかりやすく解説してもらいたい。
- **受け入れ条件**:
  - Side Panel に「Explain」タブがあり、実行ボタンを押すと結果が表示される
  - 出力が英語であること（日本語の文章が混在しない、固有名詞除く）
  - 実行中はローディング状態が表示され、ユーザーは中断・再実行できる
  - API エラー時は人間が読めるエラーメッセージが表示される（スタックトレースは UI に出さない）
  - 同一ページに対する複数回の Explain 実行ができ、結果が上書きされる
- **優先度**: Must

### F-006: Chat（ページ文脈チャット）
- **概要**: 抽出済みのページ本文をシステムコンテキストとして、ユーザーが自由にメッセージを送れるチャット UI を Side Panel に提供する。
- **ユーザーストーリー**: ユーザーとして、ページ内容について AI に質問しながら理解を深めたい。
- **受け入れ条件**:
  - Side Panel に「Chat」タブがあり、入力欄・送信ボタン・会話履歴表示がある
  - 1 ターン以上の往復ができ、過去のユーザー/アシスタント発話が画面に残る
  - 会話はページ本文をコンテキストに含めて送信される（API リクエストに本文が反映される）
  - チャット履歴はタブを閉じる、または明示クリア時に破棄され、永続化されない
  - 送信中は二重送信が防止される（送信ボタンが disabled になる）
- **優先度**: Must

### F-007: タブ切り替え（Explain / Chat）
- **概要**: Side Panel 内で Explain と Chat をタブで切り替える。
- **ユーザーストーリー**: ユーザーとして、同一の Side Panel から Explain と Chat の両方を行き来したい。
- **受け入れ条件**:
  - Side Panel にタブ UI があり、クリックで切り替わる
  - タブ切り替え時に各タブの状態（Explain 結果、Chat 履歴）が失われない（同一セッション中）
- **優先度**: Must

### F-008: ページ変更検知と状態リセット
- **概要**: アクティブタブの URL が変わった、または別タブに切り替えた際に、Side Panel の状態を新しいページのものに合わせる。
- **ユーザーストーリー**: ユーザーとして、別ページに移動したら前のページの解説や会話が混ざらないようにしたい。
- **受け入れ条件**:
  - アクティブタブの URL が変化したとき、Chat 履歴と Explain 結果がクリアされるか、現在ページと紐づかない旨の表示がされる
  - 現在表示中のページ URL が Side Panel に明示される
- **優先度**: Should

### F-009: Side Panel の起動
- **概要**: 拡張アイコンクリックまたはポップアップから Side Panel を開く。
- **ユーザーストーリー**: ユーザーとして、ワンクリックで拡張機能を呼び出したい。
- **受け入れ条件**:
  - 拡張アイコンクリック、もしくはポップアップ内のボタン押下で Side Panel が開く
  - 開いた直後に現在のアクティブタブの URL が Side Panel に反映される
- **優先度**: Must

### F-010: API キー未設定時の誘導
- **概要**: API キーが未設定の状態で Explain / Chat を実行しようとした場合、設定画面に誘導する。
- **ユーザーストーリー**: ユーザーとして、初回起動時に何をすればよいかすぐに分かるようにしたい。
- **受け入れ条件**:
  - キー未設定時の実行で「API キーを設定してください」のメッセージが表示される
  - 設定画面を開くリンク/ボタンが同時に表示される
- **優先度**: Must

### F-011: エラーハンドリングとユーザー通知
- **概要**: API エラー、ネットワークエラー、DOM 抽出エラーをユーザーに通知する。
- **ユーザーストーリー**: ユーザーとして、何が起きて失敗したのかを把握したい。
- **受け入れ条件**:
  - HTTP 4xx / 5xx / ネットワーク失敗のそれぞれに対して、原因が区別できるメッセージが表示される
  - エラーメッセージに API キー本体やリクエスト全文を含めない
  - `console.error` にはスタックトレース込みでログされる（UI には出さない）
- **優先度**: Must

### F-012: 抽出本文長の制御
- **概要**: 長大なページの場合、API へ送る本文を上限文字数で切り詰める。
- **ユーザーストーリー**: ユーザーとして、長いページでもエラーにならず Explain/Chat を試せたい。
- **受け入れ条件**:
  - 上限を超えるページでも API 呼び出しが成功する
  - 切り詰めが行われた旨が Side Panel に表示される
- **優先度**: Should

### F-013: 言語設定（解説の出力言語）
- **概要**: 解説出力言語を「英語」固定。将来的拡張のために設定はあるが、初期リリースでは英語のみ。
- **ユーザーストーリー**: ユーザーとして、解説が常に英語で得られることを期待する。
- **受け入れ条件**:
  - Explain 出力の主言語が英語である
  - 設定画面に出力言語表示があり、初期リリースでは "English" 固定
- **優先度**: Could

## 3. UI/UX 要件

### 画面一覧
- **Side Panel**:
  - 目的: Explain と Chat の主要 UI
  - 構成: ヘッダ（現在 URL 表示） / タブ（Explain | Chat） / 各タブのコンテンツ / フッタ（設定リンク）
- **Options ページ**:
  - 目的: API キー、モデル、出力言語の設定
- **Popup**:
  - 目的: Side Panel を開くトリガと、現在のページ情報の簡易表示
- **Content Script（UI なし）**:
  - 目的: DOM 抽出と選択テキスト取得

### 主要なユーザーフロー

1. **初回利用**:
   1. ユーザーが拡張アイコンをクリック
   2. Side Panel または Popup が開き、API キー未設定の旨と Options への誘導
   3. Options で API キー保存
   4. Side Panel に戻り、Explain / Chat 利用可能

2. **Explain（ページ全体）**:
   1. Side Panel で Explain タブを選択
   2. 「Explain whole page」ボタン押下
   3. Content Script が本文抽出 → background 経由で Claude API 呼び出し
   4. 結果が Side Panel に英語で表示される

3. **Explain（選択範囲）**:
   1. ページ上でテキスト選択
   2. Side Panel で「Selection only」を選び実行
   3. 選択テキストのみが API に送られ、結果表示

4. **Chat**:
   1. Chat タブを選択
   2. 入力欄にメッセージを入力し送信
   3. ページ本文を含むコンテキストで Claude API が応答
   4. 履歴が Side Panel に積み上がる
   5. タブ切替/閉じで履歴破棄

### キーボードショートカット
- 必須要件としては設定しない（Could）。Chat 入力欄では Enter 送信 / Shift+Enter 改行を Should として推奨。

## 4. スプリント計画

### Sprint 1: 基盤と設定
- **ゴール**: 拡張機能の骨格を立ち上げ、API キーとモデル設定が保存・読込できる。
- **含まれる機能**: F-001, F-002, F-009, F-010
- **依存**: なし

### Sprint 2: DOM 抽出と Explain
- **ゴール**: ページ本文を抽出し、Side Panel から英語解説を取得して表示できる。
- **含まれる機能**: F-003, F-004, F-005, F-011, F-012, F-013
- **依存**: Sprint 1

### Sprint 3: Chat と統合
- **ゴール**: ページ文脈に基づく Chat ができ、Explain とタブ切り替えで共存する。ページ変更時の状態整合が取れる。
- **含まれる機能**: F-006, F-007, F-008
- **依存**: Sprint 2

### 順序制約
- F-001/F-002 は他の API 呼び出し機能の前提
- F-003 は F-005, F-006 の前提
- F-005 と F-007 は Chat 実装（F-006）より先に存在することが望ましい

## 5. 非機能要件

### パフォーマンス
- DOM 抽出は一般的な記事ページで 2 秒以内に完了する
- Explain の API 呼び出し開始までの内部処理（抽出 → 送信）は 3 秒以内
- Side Panel の初期描画は 1 秒以内

### セキュリティ
- API キーは `chrome.storage.local` のみに保存し、`chrome.storage.sync` には書き込まない
- API キーを UI のテキストノードやログに平文で出さない
- DOM 全文をログに残さない（先頭 N 文字のサンプル程度に留める）
- Manifest の権限は必要最小限とする（過剰な host_permissions を避ける方針）
- 外部送信先は Anthropic API のみ

### アクセシビリティ
- Side Panel・Options のフォーム要素に label が紐づいている
- タブ UI はキーボード操作（Tab/Enter）で切り替えられる
- 色だけに依存した状態表示を行わない（テキストやアイコンも併用）

### ブラウザ互換性
- Chrome 安定版（Side Panel API が利用可能なバージョン、Chrome 114 以降を目安）
- Manifest V3 準拠

### プライバシー
- 閲覧/視聴履歴のトラッキングは行わない
- Chat 履歴は永続化しない（タブを閉じたら破棄）
- ページ本文は Anthropic API への送信以外に外部送信しない

## 6. 評価基準

### Sprint 1 合格基準
- 拡張機能をロード後、Options で API キーを保存し、再起動しても保持される
- `chrome.storage.sync` に API キーが書き込まれていない
- 保存済み API キーが UI 上で平文表示されない
- モデル選択が保存・反映される
- API キー未設定で Explain/Chat を起動した際に誘導メッセージが表示される

### Sprint 2 合格基準
- 一般的な記事ページで本文抽出が 2 秒以内に完了し、`<script>`/`<style>`/`<noscript>` の内容を含まない
- 「ページ全体 Explain」を実行すると、英語の解説が Side Panel に表示される
- 「選択範囲 Explain」を実行すると、選択テキストに基づく解説が表示される
- API エラー時にユーザー向けメッセージが表示され、API キーが UI に露出しない
- 上限超過ページでも API 呼び出しが成功し、切り詰め通知が表示される

### Sprint 3 合格基準
- Chat タブで 2 ターン以上の対話ができ、過去発話が表示される
- Chat の API リクエストにページ本文がコンテキストとして含まれる
- タブを閉じる/明示クリアで Chat 履歴が破棄される（次回起動時に残らない）
- Explain と Chat のタブ切り替えで各状態が同一セッション中保持される
- アクティブタブの URL 変化時に状態リセットまたは現ページと紐づかない旨の表示が行われる

### 全体の完了基準
- 上記 3 スプリントの合格基準をすべて満たす
- 非機能要件（パフォーマンス、セキュリティ、アクセシビリティ）の各項目が確認できる
- 対象外機能（Anki 連携、閲覧履歴、クイズ生成）が実装されていないこと
- `npm run check`（typecheck + build）が成功する
