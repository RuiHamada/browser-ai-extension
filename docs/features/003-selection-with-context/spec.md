# 製品仕様書: Selection Explain with Page Context

本仕様は `docs/features/001-explain-and-chat/spec.md`（F-001〜F-013）および
`docs/features/002-output-language-and-robust-extract/spec.md`（F-201〜F-204）の **拡張・上書き** である。

選択範囲 Explain（F-004 / F-005 の選択モード）において、これまで選択テキストのみを Claude に送っていたため文脈が失われ、解説の質が低下していた。
本特性では、**選択テキスト + ページ本文（コンテキスト）** を併せて送ることで、前後の文脈を加味した解説を返すようにする。

## 1. プロダクト概要

- **本特性の目的**:
  - 選択範囲 Explain の品質向上。指示語・専門用語・略語など、文脈なしには解釈が定まらない選択について、ページ全体を参照して解説させる。
  - 短い選択（数語〜1 文）でも、コンテキストがあれば実用的な解説が得られるようにする。
- **対象ユーザー**: 既存ターゲット（英語学習者・記事リーダー）と同一。特に、長い記事の中の特定の語/句を深掘りしたいユーザー。
- **対象外（明示）**:
  - iframe 内・closed Shadow DOM 内の選択範囲を取得する機能（既存仕様の制約を維持。`open` Shadow Root のみ対応継続）
  - ページ本文抽出結果のキャッシュ最適化（毎回抽出する。パフォーマンス上の問題が顕在化していないため）
  - 選択範囲の周辺段落のみを抽出する「凝った範囲指定」（ページ本文全体をコンテキストとして送るシンプル方針）
  - Anki 連携 / 閲覧履歴 / クイズ生成（プロジェクト全体の対象外）

## 2. 機能一覧（300 番台）

### F-301: 選択モードでのページ本文同時取得

- **概要**: Side Panel が「選択範囲のみ」モードで Explain を実行する際、選択テキストに加えてページ本文（F-202 の抽出結果）も同時に取得し、background へ送る。
- **ユーザーストーリー**: ユーザーとして、選択した語句を Explain したとき、そのページの内容を踏まえた解説が得られてほしい。
- **挙動仕様**:
  - 選択モードで Explain 実行時、Content Script は次の 2 つを取得する:
    1. `selectionText`: 現在のユーザー選択テキスト（空白正規化前の生テキスト、ただし前後トリム済み）
    2. `pageText`: F-202 の抽出ロジックを使ったページ本文（既存の `CONTENT_MAX_CHARS = 20000` で truncate 済み）
  - メッセージ型に `selectionText` と `pageText` の両方を載せる（discriminated union を維持）
  - 選択が空（`selectionText.length === 0`）の場合は従来通りエラー（F-004 の挙動を維持）
- **受け入れ条件**:
  - 選択モードで Explain を実行すると、background に届くメッセージに `selectionText` と `pageText` の両方が含まれる
  - `pageText` の内容が F-202 の抽出仕様（`<nav>`/`<aside>`/`<footer>`/`<header>` 除外、`<main>`/`<article>` 優先、`open` Shadow Root 走査、空白正規化）に従っている
  - 選択が空のときは API 呼び出しが行われず、F-004 と同等のエラーメッセージが表示される
  - 選択テキストが iframe / closed Shadow DOM 内に由来し取得できないケースでは、`selectionText` が空文字として扱われ、上記の選択空エラー経路に乗る（クラッシュしない）
  - `pageText` 抽出に失敗した（空文字になった）場合でも、`selectionText` が非空であれば API 呼び出しは選択テキストのみで実行される（フォールバック動作）
- **優先度**: Must
- **既存上書き**: F-004 の搬送内容を上書き（選択モードでも `pageText` を併送する）。

### F-302: 文脈付き Explain プロンプト

- **概要**: 選択モードの Explain で、Claude に送るリクエスト本文に「ページ本文（参考）」と「選択テキスト（解説対象）」を構造化して同梱する。
- **ユーザーストーリー**: ユーザーとして、選択した語句がページの中でどう使われているかを踏まえた解説を受け取りたい。
- **プロンプト設計（固定）**:
  - user content の構造（テキスト形式）:
    ```
    Page context (for reference, do not summarize this):
    <page>
    {pageText}
    </page>

    Explain the following selection within that context:
    <selection>
    {selectionText}
    </selection>
    ```
  - `pageText` は F-301 で truncate 済み（`CONTENT_MAX_CHARS = 20000`）の値をそのまま埋め込む
  - `selectionText` は本仕様の上限 `SELECTION_MAX_CHARS = 5000` で truncate する。超過時は末尾に `…` を付加し、`pageText` と同様にどこかで「選択が長すぎたため切り詰めた」旨を Side Panel に表示する（F-012 の切り詰め通知 UX に準ずる）
  - 出力言語は F-201 の `outputLanguage` 設定に従う（システムプロンプト側に従来通り言語指示を含める）
  - 選択モードでなくページ全体 Explain の場合、本プロンプト構造は使わず従来の単一本文プロンプトを継続する
- **受け入れ条件**:
  - 選択モードで Explain を実行したとき、Anthropic API への user メッセージ本文に `Page context` セクションと `Explain the following selection` セクションの両方が含まれ、それぞれに `pageText` と `selectionText` の内容が入っている（モック API の単体テストで検証可能）
  - `pageText` が 20000 文字、`selectionText` が 5000 文字の上限に達した場合、リクエスト本文の該当セクションがそれぞれの上限以下に収まる
  - `selectionText` が 5000 文字を超えたケースで Side Panel に切り詰め通知が表示される
  - `outputLanguage = "ja"` のとき、応答の主言語が日本語である（F-201 の挙動を引き継ぐ）
  - `outputLanguage = "en"` のとき、応答の主言語が英語である
  - `pageText` が空（抽出失敗）の場合、プロンプトは `Page context` セクションを省略し、選択テキストのみで従来同等のリクエストを送る（F-301 のフォールバック動作と整合）
  - ページ全体 Explain（選択モードではない）のリクエスト本文には `Page context` / `Explain the following selection` のラベルが含まれない（既存挙動の維持）
- **優先度**: Must
- **既存上書き**: F-005 の選択モード時のリクエスト構造を上書き。

### F-303: 選択モードにおける短文警告の見直し

- **概要**: F-203 の「抽出結果 40 文字未満で警告」ルールを、選択モードに限り変更する。選択モードでは選択テキストとページ本文を合わせて Claude に送るため、選択が短くてもコンテキストが補えるケースが多い。
- **方針決定（Planner 判断）**:
  - **選択モードでは F-203 の短文警告を抑止する**（警告 UI を出さず、即実行する）
  - 理由:
    1. ページ本文がコンテキストとして併送されるため、Claude 側で語義/用法を解釈する材料が十分にある
    2. 選択モードのユースケースは「短い語句や 1 文を選んで深掘りしたい」が主であり、毎回警告ダイアログを挟むと UX が劣化する
    3. 「合算長で判定」案も検討したが、`pageText` の長さは選択直前の抽出に依存し、ユーザーが警告の発火条件を予測しづらい。仕様の簡潔さを優先した
- **挙動仕様**:
  - 選択モード（`mode === "selection"`）の Explain では、`selectionText` の長さに関わらず F-203 の警告 UI を表示しない
  - ただし F-204 の短文用システムプロンプト切替は維持する。判定基準は `selectionText.length < 40`（`pageText` は判定に含めない）
  - ページ全体モード（`mode === "whole"`）では F-203 の挙動を変更しない（従来通り 40 文字未満で警告 UI）
  - 選択が空のケースは F-004 / F-301 の通り「警告」ではなく「エラー」（変更なし）
- **受け入れ条件**:
  - 選択モードで `selectionText` が 40 文字未満かつ非空のとき、警告 UI（`Run anyway` / `Cancel`）が表示されず、即座に API 呼び出しが行われる
  - 選択モードで `selectionText` が 1 文字 〜 39 文字のいずれの長さでも、API リクエストの user content に `Page context` と `Explain the following selection` の両方が含まれる
  - 選択モードで `selectionText.length < 40` の場合、システムプロンプトに F-204 の短文解説指示が含まれる（モック API の単体テストで検証）
  - ページ全体モードで抽出本文が 40 文字未満のときは、引き続き F-203 の警告 UI が表示される（リグレッションなし）
  - 選択モードで選択が空のときは、警告ではなくエラーメッセージが表示される（F-004 / F-301 の挙動）
- **優先度**: Must
- **既存上書き**: F-203 の発火条件を選択モードについて上書き。F-204 の判定基準を選択モード時は `selectionText` 長に固定。

## 3. UI/UX 要件

### 画面差分

- **Side Panel（Explain タブ）**:
  - 選択モードで Explain 実行時、ローディング中の補足として「ページ本文も参照しています」相当の控えめなテキストを表示する（任意。Generator の判断で省略可）
  - F-303 により選択モードでは短文警告ブロックが出現しなくなる
  - `selectionText` が 5000 文字超過で切り詰めが発生した場合、F-012 と同じスタイルで切り詰め通知を表示する

### フロー差分

1. **選択 Explain（短い選択）**:
   1. ユーザーがページ上で 1 語（例: `notable`）を選択
   2. Side Panel で「Selection only」モードを選び Explain 実行
   3. Content Script が `selectionText` と `pageText` の両方を取得
   4. background が文脈付きプロンプトで Claude API を呼び出す
   5. 応答（ページ文脈を踏まえた語義解説）が `outputLanguage` の言語で表示される
   6. **警告 UI は表示されない**（F-303）

2. **選択 Explain（長い選択）**:
   1. ユーザーが 1 段落以上の長文を選択
   2. Explain 実行
   3. `selectionText` が 5000 文字超過なら切り詰め通知が出る
   4. 文脈付きプロンプトで API 呼び出し → 応答表示

3. **ページ全体 Explain**:
   - 従来通り（本特性の影響なし）

### アクセシビリティ
- 既存の Side Panel A11y 要件（label 紐づけ・ARIA 等）を維持。新規 UI 追加が最小であるため追加要件は設けない。

## 5. 非機能要件（差分）

### パフォーマンス
- 選択モードでもページ本文抽出を毎回実行するが、F-202 の 2 秒以内 SLA を維持する
- 選択 + ページ本文の合算長が API 上限を超えないよう、`SELECTION_MAX_CHARS = 5000` と `CONTENT_MAX_CHARS = 20000` の合計 25000 文字 + プロンプトテンプレートのオーバーヘッドが Anthropic API の入力上限に十分収まることを確認する

### セキュリティ / プライバシー
- ページ本文を併送する範囲が広がるが、外部送信先は Anthropic API のみ（既存方針の維持）
- DOM 全文ログ禁止の方針を維持（先頭 N 文字サンプルのみ）
- API キーの UI / ログ露出禁止（F-013 維持）

### 互換性
- 既存ユーザーの設定（`outputLanguage` 等）に対するマイグレーション不要
- メッセージ型を拡張する場合、background が古い形式（`selectionText` のみ）を受け取った場合でもクラッシュしないよう後方互換に配慮する（実装は Generator が判断）
