# 製品仕様書: 出力言語切替 & DOM 抽出堅牢化

本仕様は `docs/features/001-explain-and-chat/spec.md`（F-001〜F-013、Sprint 1〜3 実装済み）の **拡張・改善** である。
既存機能を破壊しない範囲で、出力言語の切替・DOM 抽出の信頼性向上・短文時の挙動改善を行う。

---

## 0. 既存仕様との関係

本特性で追加・上書きされる既存機能 ID と差分の概要を先に明示する。

| 既存 ID | 既存挙動 | 本特性での扱い | 上書き内容 |
|---------|----------|----------------|------------|
| F-003 ページ本文 DOM 抽出 | `<script>`/`<style>`/`<noscript>` のみ除外 | **F-202 が上書き** | `<nav>`/`<aside>`/`<footer>`/`<header>` を追加除外、`<main>`/`<article>`/`[role="main"]` 優先、Shadow DOM 対応、空白正規化 |
| F-005 Explain | 出力は英語固定 | **F-201 が拡張、F-204 が補強** | 出力言語を `outputLanguage` 設定に従わせる。短文入力時は語の意味解説を行う |
| F-006 Chat | 応答言語は暗黙（英語想定） | **F-201 が拡張** | 応答言語を `outputLanguage` 設定に従わせる |
| F-012 抽出本文長の制御 | 上限超過時の切り詰めのみ | **F-203 が補強** | 抽出結果が極端に短い（下限未満）の場合の警告と確認 UI を追加 |
| F-013 言語設定 | "English" 固定表示のみ | **F-201 が完全に上書き** | Options で `English`/`Japanese` を選択可能にし、永続化する |

既存 F-001/F-002/F-004/F-007〜F-011 は変更しない。

## 1. プロダクト概要

- **本特性の目的**:
  - 学習者が出力言語を自分の理解度に合わせて切り替えられるようにする（英語学習中→英語、内容把握優先→日本語）
  - 一般 Web ページで本文抽出が事実上失敗する（`"notable"` 1 語しか取れない等）バグの解消
  - 抽出結果が極端に短いケースでも、ユーザーが意図して投げたいときに違和感なく解説が得られるようにする
- **対象ユーザー**: 既存ターゲット（英語学習者・記事リーダー）と同一
- **対象外（明示）**:
  - Anki 連携・閲覧履歴トラッキング・クイズ生成（プロジェクト全体の対象外）
  - 出力言語の **自動判定**（明示選択のみ。ブラウザロケール検出も対象外）
  - 抽出結果のキャッシュ永続化（セッション内のみ）
  - 出力言語に英語・日本語以外を追加すること

## 2. 機能一覧（200 番台）

### F-201: 出力言語の選択（Options + クイック切替）

- **概要**: Options ページで出力言語 `English` / `Japanese` を選択でき、Side Panel 上にもクイック切替 UI を備える。Explain と Chat の応答言語が選択値に従う。
- **ユーザーストーリー**: ユーザーとして、英文解説と日本語解説をワンクリックで切り替えたい。
- **設定キー仕様（固定）**:
  - キー名: `outputLanguage`
  - 値: `"en" | "ja"`
  - デフォルト: `"en"`
  - 保存先: `chrome.storage.local`（`sync` には保存しない）
- **受け入れ条件**:
  - Options ページに `English` / `Japanese` のラジオまたはセレクトがあり、保存後 `chrome.storage.local` の `outputLanguage` がそれぞれ `"en"` / `"ja"` になる
  - 既存ユーザー（`outputLanguage` キーが未保存）の起動時、デフォルト `"en"` として扱われる
  - Side Panel に出力言語のクイック切替 UI（トグルまたはセレクト）が表示され、変更が `chrome.storage.local` に即時反映される
  - `outputLanguage = "ja"` で Explain を実行すると、応答本文の主言語が日本語である（コード/固有名詞/英単語の引用を除く）
  - `outputLanguage = "en"` で Explain を実行すると、応答本文の主言語が英語である
  - `outputLanguage = "ja"` で Chat を送信すると、応答の主言語が日本語である
  - Side Panel と Options の両方で値を変更したとき、最後に保存した値が次回起動時にも保持される
- **優先度**: Must
- **既存上書き**: F-013 を完全に置き換える。F-005 / F-006 のプロンプト言語固定箇所を上書きする。

### F-202: DOM 抽出の堅牢化

- **概要**: 一般 Web ページで本文抽出が 1〜数語に潰れる事象を解消する。除外タグ拡張・本文コンテナ優先・Shadow DOM 探索・空白正規化を行う。
- **ユーザーストーリー**: ユーザーとして、ニュース記事・ブログ・ドキュメントサイトなど一般的なページで本文がきちんと取れていることを期待する。
- **抽出仕様**:
  - 除外タグ（テキスト本文に含めない）:
    - 既存: `<script>`, `<style>`, `<noscript>`
    - 追加: `<nav>`, `<aside>`, `<footer>`, `<header>`, `<form>`, `<svg>`, `<iframe>`, `<template>`, `aria-hidden="true"` の要素, `hidden` 属性のある要素
  - 本文コンテナ優先順:
    1. `<main>` 要素（複数あれば最初）
    2. `<article>` 要素（複数あれば最大の `innerText` 長を持つもの）
    3. `[role="main"]`
    4. 上記いずれも存在しない / 抽出文字数が下限未満の場合は `<body>` をフォールバック
  - Shadow DOM: `open` な Shadow Root を再帰的に走査して本文として取り込む（`closed` は不可）
  - 空白正規化: 連続する空白・改行を 1 つの空白に圧縮、前後トリム
  - 文字数: F-012 の上限制御は維持
- **受け入れ条件**:
  - `<main>` 配下に本文を持つページの抽出結果が、`<nav>` 配下のリンクテキストを含まない
  - `<article>` を持つページで、`<header>` 内のサイトナビ文字列が抽出結果先頭に来ない
  - `<script>` / `<style>` / `<noscript>` の中身を含まない（既存条件の維持）
  - `aria-hidden="true"` を付けた要素のテキストが抽出結果に含まれない
  - `open` Shadow Root 内のテキストが抽出に含まれる（`closed` Shadow Root は対象外でよい）
  - 抽出は一般的な記事ページで 2 秒以内に完了する（既存パフォーマンス要件の維持）
  - 同一の再現用ページ（テスト用 fixture）で `"notable"` のような単語 1 語しか取得できない既存バグが再発しない
- **優先度**: Must
- **既存上書き**: F-003 の抽出ロジック規定を上書きする。

### F-203: 短い抽出結果に対する警告 UI

- **概要**: 抽出結果が極端に短い場合、ユーザーに警告を提示し、明示的な確認操作を経てから API 呼び出しを行う。
- **閾値（仕様で固定）**:
  - **下限文字数**: `40` 文字（空白正規化後の長さ）
  - 下限未満の場合のみ警告対象
- **ユーザーストーリー**: ユーザーとして、ページの本文がほぼ取れていない状態で API を呼んで意味のない応答が返る前に、状況を知りたい。
- **受け入れ条件**:
  - 抽出結果（選択範囲 or ページ本文、実行モードに応じる）が 40 文字未満のとき、Side Panel に警告メッセージと「このまま実行」「キャンセル」ボタンが表示される
  - 警告状態では、ユーザーが「このまま実行」を押すまで API 呼び出しは行われない
  - 警告メッセージには抽出文字数（例: `extracted 7 chars`）が含まれる
  - 「キャンセル」を押すと API 呼び出しは行われず、ローディングも発生しない
  - 抽出結果が 40 文字以上の通常ケースでは警告は表示されず、従来どおり即実行される
  - 「Selection only」モードで選択が空のときの挙動（F-004）は変更されない（警告ではなくエラー）
- **優先度**: Must
- **既存上書き**: F-012 を補強する（切り詰めの上限側に対して、下限側の挙動を追加）。

### F-204: 短文入力に対するプロンプト改善

- **概要**: Explain で抽出結果が極端に短い（数語〜短文）場合でも、その語/句の意味・用法を解説する応答が返るようにシステムプロンプトを設計する。
- **ユーザーストーリー**: ユーザーとして、単語選択や 1 行コードに対しても Explain が機能してほしい。
- **挙動仕様**:
  - 入力本文長が 40 文字未満（F-203 の下限と同一）の場合、システムプロンプトに「入力が短い場合はその語/句/式の意味・用法・典型的な文脈を解説せよ」という指示を含める
  - 入力本文長が 40 文字以上の場合は通常の解説プロンプトを使う
  - 出力言語は F-201 の `outputLanguage` 設定に従う
- **受け入れ条件**:
  - 入力 `"notable"`（1 語）に対する Explain 応答が、空応答や「情報不足」拒否ではなく、その語の意味・用法に関する説明を含む
  - 入力 `"const x = 1;"`（短い式）に対する Explain 応答が、その式の意味に関する説明を含む
  - `outputLanguage = "ja"` のとき、上記応答の主言語が日本語である
  - 入力が通常長（40 文字以上の本文）の場合の応答品質に明確な低下が出ない（既存 Sprint 2 合格基準を満たし続ける）
- **優先度**: Should
- **既存上書き**: F-005 のプロンプト規定を補強する。

## 3. UI/UX 要件

### 画面差分

- **Options ページ**:
  - 出力言語セクションを追加: `English` / `Japanese` の二者択一
  - 既存の「言語: English 固定」表示は削除
- **Side Panel**:
  - ヘッダ付近にクイック言語切替（例: `EN | JA` のセグメント、または小さなセレクト）を追加
  - 短文時の警告ブロック（F-203）を Explain タブのアクション領域に追加。`extracted N chars` の表示と `Run anyway` / `Cancel` ボタンを含む

### フロー差分

1. **言語切替フロー**:
   1. ユーザーが Side Panel のクイック切替で `JA` を選択
   2. `chrome.storage.local.outputLanguage = "ja"` が即時保存
   3. 以降の Explain / Chat の応答が日本語で返る
2. **短文警告フロー**:
   1. ユーザーが Explain を実行
   2. 抽出結果長が 40 文字未満
   3. 警告ブロックが表示され API 呼び出しは保留
   4. `Run anyway` で短文用プロンプト（F-204）にて API 実行
   5. `Cancel` で何もせず待機状態に戻る

### アクセシビリティ
- 言語切替 UI に label を紐づけ、現在選択中の言語をテキストでも示す（色のみで区別しない）
- 警告ブロックは `role="alert"` 相当の通知扱いとする

## 4. スプリント計画

本特性は 2 スプリントに分割する。

### Sprint 4: 出力言語切替

- **ゴール**: `outputLanguage` 設定が Options と Side Panel から変更でき、Explain / Chat の応答言語が一貫して切り替わる。
- **含まれる機能**: F-201
- **依存**: Sprint 1〜3（既存実装）
- **合格基準**:
  - `chrome.storage.local.outputLanguage` のデフォルトが `"en"`、保存値 `"en" | "ja"` のみ
  - Options で言語を変更すると保存され、再起動後も保持される
  - Side Panel のクイック切替で値を変えると、次の Explain / Chat 応答に反映される
  - `outputLanguage = "ja"` での Explain / Chat 応答が主に日本語で、`"en"` では主に英語であることを自動テストで確認できる（システムプロンプトに言語指示が含まれることの単体テスト + 応答整形を検査するスナップショット/契約テスト）
  - `chrome.storage.sync` に `outputLanguage` が書き込まれない

### Sprint 5: DOM 抽出堅牢化と短文対応

- **ゴール**: 一般 Web ページで本文がほぼ取れない事象が解消し、短文時もユーザーの意図に沿った挙動になる。
- **含まれる機能**: F-202, F-203, F-204
- **依存**: Sprint 4（プロンプト言語切替が前提）
- **合格基準**:
  - F-202 受け入れ条件のすべてを満たす（fixture HTML を用いた抽出関数の単体テストが緑）
  - 既存バグ再現 fixture（`<header>` のみが拾われ "notable" になるケース）で本文が取得できる
  - 抽出結果 40 文字未満のとき UI に警告が出て、API 呼び出しが `Run anyway` 押下まで発生しない（DOM テストで確認）
  - `"notable"` 入力で Explain を `Run anyway` 実行したとき、応答が空でないこと（モック API でプロンプトに短文指示が含まれることを検証）
  - 既存 Sprint 2/3 合格基準が引き続き通る（リグレッションなし）

### 順序制約
- F-201 → F-204（言語切替がプロンプト分岐の前提）
- F-202 → F-203（抽出仕様確定後でないと閾値判定が安定しない）

## 5. 非機能要件（差分）

### パフォーマンス
- F-202 の堅牢化後も DOM 抽出は一般的な記事ページで 2 秒以内に完了する
- Shadow DOM 探索の再帰深度は実装側で安全制限を設ける（無限ループを起こさない）

### セキュリティ / プライバシー
- `outputLanguage` 設定値は機微情報ではないが、既存方針に合わせ `chrome.storage.local` に保存する
- 抽出範囲が広がっても、DOM 全文ログ禁止の方針は維持する（先頭 N 文字サンプルのみ）

### 互換性
- 既存ユーザーの `chrome.storage.local` に `outputLanguage` が無い場合でもクラッシュせず `"en"` として動作する（マイグレーション不要）
